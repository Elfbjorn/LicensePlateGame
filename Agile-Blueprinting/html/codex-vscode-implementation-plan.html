Codex VS Code Implementation Plan

This plan describes how to operationalize the MVP Agile Blueprinting workflow in Codex, with the first target surface being Codex in VS Code.

Objective

Make the first useful Agile Blueprinting workflow available as guided Codex skills so users do not need to understand the full methodology before producing useful artifacts.

Plugin Model

Use team-oriented plugins:

Plugin Audience Initial MVP Skills
Product plugin Product, Design, BA-style discovery prd-generator, prd-readiness-review
Engineering plugin Engineering, QA, DevOps execution implementation-agent, unit-test-agent, e2e-test-agent
Operations plugin Support/Ops Deferred until Support/Ops workflows are defined

MVP Rollout Sequence

  1. Prototype prd-generator in the Product plugin.
  2. Validate generated PRDs against PRD-TEMPLATE.md.
  3. Add prd-readiness-review.
  4. Add implementation-agent.
  5. Add unit-test-agent.
  6. Add e2e-test-agent.
  7. Revisit frontmatter and workflow state after teams use the MVP skills on real work.

VS Code Usage Model

The user should invoke a skill from the relevant plugin and answer guided prompts.

Expected flow:

  1. User starts in a repo or workspace.
  2. User invokes a skill such as prd-generator.
  3. Codex asks for required variables and context.
  4. Codex writes or updates the appropriate Markdown artifact.
  5. Codex includes YAML frontmatter for status, ownership, and future automation.
  6. Codex identifies open questions, assumptions, risks, and required human review.

MVP Completion Criteria

The Codex MVP is complete enough for first use when:

  • The Product plugin has a working prd-generator skill.
  • The first PRD can be generated from guided questions.
  • The output follows the PRD/blueprint frontmatter shape.
  • The output includes open questions and assumptions instead of hiding missing answers.
  • The generated PRD can be reviewed by Product and Engineering without the user manually assembling the template.

Later-Phase Work

  • Operations plugin skills.
  • Run initialization skill.
  • Artifact review and SPOG generation.
  • Full workflow state handling.
  • Marketplace packaging/install flow.
  • Web/database-backed workflow and HITL review.
