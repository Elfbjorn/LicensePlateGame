Single Pane of Glass

The Single Pane of Glass is the final HITL review dashboard for Blueprint to Release. It consolidates the evidence produced by the LLM and specialist agents into a KPI-style review surface so humans can approve, reject, hold, or redirect the work.

Nothing should reach this stage unless each prior tollgate has a recorded HITL review.

Dashboard Principles

  • Show status at a glance using stoplights, gauges, and clear readiness indicators.
  • Provide one KPI card per tollgate.
  • Group KPI cards into lifecycle phases so the page can be scanned before individual widgets are reviewed.
  • Show phase-level rollups even when the detailed widget section is collapsed.
  • Summarize agent evidence into human-readable status.
  • Allow drill-down from each KPI into the detail behind it.
  • Show who reviewed each tollgate, when they reviewed it, and what they decided.
  • Distinguish agent conclusions from human certification.
  • Make disagreement explicit and reviewable.
  • End with a final ship/hold recommendation and decision log.

Dashboard Phases

The SPOG should not present every widget as one long undifferentiated wall. It should group the review surface into collapsible lifecycle phases. Department ownership still matters, but the primary leadership question is where the work sits in the delivery path and whether that phase is ready, risky, blocked, waiting, or not applicable.

Recommended phase model:

Phase Purpose Included Widgets
Intake & Direction Confirm the request is understandable, categorized, routed, and directionally approved Intake Triage; Ticket Categorization; Delivery Lane Selection; Customer / Proxy Direction Review; Amendment / Re-Scope Review
Blueprint Readiness Confirm the customer need, blueprint, and handoff criteria are ready enough to govern delivery Discovery Readiness; PRD / Blueprint Review; Definition of Ready; Agent Planning Review
Build & Evidence Confirm implementation and validation evidence are sufficient for human review Implementation Review; Pull Request Review; Testing Review; Acceptance Validation; Security / Risk Review
Release Readiness Confirm documentation, packaging, deployment, consolidated evidence, and ship/hold decision are ready Documentation / Comms Review; Packaging Review; Deployment Review; SPOG / Evidence Review; Final Ship / Hold Decision
Post-Release & Closure Confirm production outcome, requester acceptance, and closure evidence Post-Release Validation; Closure / Done Review

Each phase header should show:

  • total widget count
  • green count
  • yellow count
  • red count
  • blue count
  • gray count
  • phase recommendation or posture

Example collapsed phase header:

Phase Widgets Green Yellow Red Blue Gray Phase Posture
Build & Evidence 5 4 1 0 0 0 Proceed with accepted testing follow-up

The page may use accordions, collapsible panels, or another equivalent interaction pattern. The key requirement is that the collapsed view remains meaningful without forcing leadership to inspect every widget.

Final Notes

  • The dashboard should make it impossible to confuse an agent recommendation with a human decision.
  • Agent disagreement or unresolved risk is not automatically a blocker, but it must be visible and explicitly accepted or rejected by the right human reviewer.
  • No pull request may be approved solely by an agent.
  • No release may proceed unless the required HITL tollgates are signed off.
